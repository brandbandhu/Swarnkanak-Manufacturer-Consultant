# Swarnakanta Agro Hub

PROJECT TITLE:
Swarnkanak Manufacturer & Consultant – Agricultural Machinery Ecommerce and Customer Portal

PROJECT OBJECTIVE:
Build a complete, ready-to-deploy, multi-page agricultural machinery ecommerce website and secure customer portal for “Swarnkanak Manufacturer & Consultant”.

This must not be only a normal company website. It must function as a complete ecommerce portal with:

1. Public product-oriented company website
2. Customer registration and login
3. Individual customer dashboards for approximately 800–850 users
4. One secure Super Admin dashboard
5. Product catalogue and product-detail pages
6. Shopping cart and checkout process
7. Order and enquiry management
8. Offers and promotional-banner management
9. Website-content management
10. Product, user and portal-activity management

The first version must contain realistic dummy data and working demo flows so it can be presented to the client and used to explain how the final portal will operate.

TECHNOLOGY STACK:
Use:

- React.js with Vite for the frontend
- Node.js and Express.js for the backend
- MySQL for the production database
- JavaScript only
- CSS or Tailwind CSS for styling
- JWT authentication
- bcrypt password hashing
- REST APIs
- Multer or an equivalent secure upload system
- Recharts or Chart.js for dashboard charts
- React Router for routing
- Axios for API communication
- React Hook Form with Yup or Zod validation

Do not build a simple static mock-up. Create a backend-ready, database-ready and deployment-ready portal structure.

Registration validations:
- Username must be unique
- Mobile number must be unique
- Valid Indian mobile-number format
- Password minimum 8 characters
- Password must include uppercase, lowercase, number and special character
- Confirm-password match
- Terms must be accepted

Registration flow:
1. Customer completes the form
2. Frontend validates fields
3. Mobile OTP verification demo
4. Account is created
5. Welcome notification is displayed
6. User is redirected to Login or Dashboard
7. Admin can see the new registration
8. Registration activity is stored in logs

For the demo version, use a visible demo OTP such as 123456, but structure the backend so a real SMS provider can be added later.

LOGIN PROCESS:
Login fields:
- Username or Phone Number
- Password
- Remember Me
- Forgot Password

Login flow:
1. User enters username/phone and password
2. Backend verifies credentials
3. JWT access token is issued
4. User is redirected according to role
5. Admin goes to Admin Dashboard
6. Customer goes to Customer Dashboard
7. Login date, time and IP/device metadata are logged
8. Failed login attempts are tracked
9. Account lockout can be enabled after repeated failures

Add:
- Show/hide password
- Session expiry
- Logout from all devices
- Secure refresh-token structure
- CAPTCHA-ready placeholder

FORGOT-PASSWORD FLOW:
1. Enter registered phone number or email
2. Verify OTP
3. Enter new password
4. Confirm password
5. Show password reset success
6. Redirect to login
